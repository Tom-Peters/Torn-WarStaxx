# War-TornStaxx | Deep code and UX audit | 5 November 2026

**Audited source:** `WarStaxx.user.js`, v1.5.0 through v1.5.1.
**Scope:** runtime boot and Torn PDA parse safety; official Torn API parsing, backoff and cache; own/opponent faction state; WarStaxx hub event contract; ranked-war target roles, manual HIT and heal flows; Black Skulls assignment and replacements; shared Worker boundary; report provenance; page strip; three modal screens; touch and keyboard usability.

## Functional review notes

- **Faction detection:** own-faction ID is resolved from the user's read-only Torn API; no fallback to a player ID. Manual faction switching now invalidates old transient data.
- **Role segregation:** Black Skulls receive only known upper-BSS bracket targets; non-Black-Skulls receive lower-BSS targets. Unknown BSS is not silently classified as weak.
- **Fight advice:** recent manual comparative battle-stat spies, dated official rosters, known losses, user-selected risk policy and saved targets govern the conservative recommendation. FFScouter values remain estimates, not guaranteed wins.
- **Orders:** local assignments, Black Skulls roles, control duties, guarded replacement and draft actions are user-directed. The script never automatically attacks or uses items.
- **Intelligence provenance:** previous ranked-war scores and member contributions come from reports, whereas travel, status and scoring pace from limited observed samples are labelled as such.
- **API and FF:** Torn v2 endpoints are read-only, throttled and have backoff. FFScouter requires explicit opt-in. Third-party FF access and external shared Worker are not exercised without user keys.
- **Shared Worker:** only deliberately enabled order/policy fields are exported; no Torn API key, FF key, manual spy values or activity logs are published in the payload. Sync has revision-conflict handling and is disabled by default.
- **Hub:** `war` module ID and `staxx:open/register/summary/actions/notice` contract remain unchanged. The shared fifth TornStaxx launcher stays a separate script.

## Remaining validation, not claims of successful device testing

- Run `npm test` in a checked-out repository on a Node-capable machine; the source and test fixtures were evaluated in an isolated JavaScript test harness during this audit, but this is not a GitHub Actions or full device run.
- Verify Torn PDA injection on an actual Android WebView: script registration, main hub launch, deep links to `leader` / `skulls` / `operations`, and return from item and attack pages.
- Test visual rendering at 320px, 360px, 390px and tablet widths with both mobile keyboard open and ordinary scroll; CSS was reviewed statically, not screenshot-tested on a physical device.
- Verify selected Torn API permission scope for current wars, members, chain, ranked war history/reports and optional faction attack logs. Empty/error responses must remain clearly unknown.
- Check FFScouter paid/free registration and TTL with real opt-in credentials; validate 429 responses and unavailable estimates.
- Where a shared Worker is configured, test remote revision conflict, read-only role, authorisation and two-browser consistency before relying on shared squad orders.
- During an active war, check one real hospital-exit or inbound-travel transition, an assigned Black Skull target, a blocked unsafe target, a post-heal HIT and the 10-second chain display.

## Visual/interaction follow-ups still worth considering

- Some older informational successes are written into `state.error` and shown with warning styling. Separating neutral confirmation messages from errors would improve visual meaning.
- Very wide reports intentionally scroll horizontally on phones. A future compact card layout for high-use mobile tables would reduce horizontal scanning without dropping historical detail.
- Heavy live decision panels can be expensive on older Torn PDA WebViews, since many conservative matchup checks inspect local attack history. Performance should be profiled on-device rather than assuming desktop parser success guarantees smooth gameplay.

**Installer stability:** `https://raw.githubusercontent.com/Tom-Peters/Torn-WarStaxx/main/WarStaxx.user.js` unchanged. All v1.5.1 changes preserve user config keys and existing saved war data except the explicitly described transient identity cache reset.
